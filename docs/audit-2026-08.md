# NWSA Music Hub — Full-Stack Audit (August 2026)

**Scope:** Director & administrative UX · overall UX/UI & information architecture ·
security & data protection · application architecture & tech upgrades · actionable roadmap.

**Method:** Four parallel code auditors (director UX, public UX/accessibility, security,
architecture) read the live codebase end-to-end; every critical/high security claim was then
independently re-verified against the cited code by adversarial reviewers, and a final
completeness pass swept the areas the first four missed (scripts/, the notification relay,
destructive tooling). Every finding below cites real `file:line` evidence. 48 findings survived
verification; none were refuted.

---

## Executive summary

**This is an unusually well-engineered app for a volunteer-maintained school project.** Before
the findings, what the audit *confirmed works* — because the recommendations only make sense
against this baseline:

- **Attendance is already best-in-class for the podium use case.** Exception-only marking
  (everyone defaults to present; an all-present roll is one "Finish roll" tap), one-tap
  Absent/Late/Excused/Lesson per student on ≥48px buttons, optimistic writes with haptics,
  a persistent retry tray, planned-absence "reported ahead" chips, same-day cross-period
  context, 5-rehearsal history dots, seating-chart tap-to-cycle mode, and roll receipts with
  who/when attribution.
- **Offline fundamentals are in place.** Firestore `persistentLocalCache` means a roll taken in
  a dead zone syncs when signal returns; a service-worker app shell, PWA manifest, and an
  update toast exist; the public/director code split is real and lint-enforced, so parents
  never download chart.js or the director UI.
- **The authorization model is genuinely good.** A data-driven allowlist (`directors/{email}`)
  with four roles (owner/director/teacher/assistant), deny-by-default rules, owner-only role
  management, diff-checked assistant writes scoped to assigned ensembles, and append-only
  audit logs.
- **Secrets hygiene is clean.** No Anthropic key anywhere in the client (the `@anthropic-ai/sdk`
  devDependency is unused in `src/`), the Firebase service account lives only in a GitHub
  Actions secret, and git history contains no committed keys. The Firebase web config being
  public is by design and is not a finding.
- **XSS surface is minimal.** All user text renders through React text nodes; `Linkify` is
  scheme-restricted; the only `dangerouslySetInnerHTML` renders self-generated QR SVG.

The serious problems cluster in four places:

1. **Student PII (top risk).** The real 2025-26 roster — 86 minors' full names, grades,
   instruments — is committed to the repo and compiled into the publicly served director JS
   chunk; independently, the `students` collection is world-readable via unauthenticated
   Firestore REST, and per-student ICS feeds are published as static files. There is no
   opt-out mechanism (FERPA directory-information exposure).
2. **A live data-destruction footgun.** The July-2026 "Redesign test data" reset panel still
   ships in the production Roster screen: any full director is one typed `RESET` away from
   non-atomically wiping ten collections (all attendance history included) and re-importing
   *last year's* roster. No export, no backup, no meaningful undo.
3. **The offline story fails at its edges.** The hand-rolled service worker can cache a GitHub
   Pages 404 page *as the app shell* (offline boot reload-loop), precaches no JS/CSS (offline
   boot silently breaks after every deploy), and non-attendance forms hang on "Saving…"
   forever when offline even though the write queued successfully.
4. **Silent operational failures.** The school-closure quick action never reaches the
   Power Automate parent/Teams relay; the deploy-time ICS generator can corrupt every
   subscribed calendar feed with one multi-line note, and swallows total failure with a green
   build.

Everything else is polish — much of it low-effort because the codebase already contains the
right pattern and just doesn't apply it everywhere (dark-mode overrides, `useModalA11y`,
translation keys that exist but are never wired up).

## 1. Director & administrative UX (high priority)

### 1.1 Attendance & roll-taking

**Verdict: the workflow design is right; fix the mechanics under it.** The exception-only
model already beats the QR/kiosk alternatives for this context (see 1.4).

| # | Finding | Severity | Effort |
|---|---------|----------|--------|
| D1 | Roll-list memoization is defeated: every tap re-renders all 60–80 cards | Medium | Low |
| D2 | "Take Roll" deep link drops `eventId` → opens the wrong period when an ensemble meets twice in a day | Medium | Low |
| D3 | On-screen hint teaches an interaction that doesn't exist ("tap to cycle", "Tardy") | Low | Low |
| D4 | Unbounded all-attendance listener mounted inside the roll screen | Low | Medium |
| D5 | Rapid same-student correction taps silently swallowed while a write settles | Low | Medium |
| D6 | Undo tray holds only one undo at a time | Low | Low |
| D7 | TodayView "Roll in progress — N marked" counts other periods' and Lesson records | Low | Low |

**D1 — the hottest path in the app re-renders everything on every tap.**
`StudentCard` is memoized precisely so "a single tap [doesn't] re-render them all"
(`StudentCard.tsx:94-95`), but `RollPeriod` passes plain inline functions
(`AttendanceView.tsx:378,391`), so the memo's shallow compare fails on every card, every tap.

```tsx
// AttendanceView.tsx — stabilize the two callbacks StudentCard receives
const handleToggle = useCallback(
  async (studentId: string, status: AttendanceStatus) => { /* existing body */ },
  [toggleAttendance, period.event?.startTime, date],
);
const handleLessonTap = useCallback(
  async (student: Student) => { /* existing body */ },
  [lessons, deleteOverride, recordMap],
);
```

**D2 — wrong-period roll marks.** `TodayView.tsx:354` sends only
`{ ensembleId: event.ensembleIds[0] }`; `AttendanceView.tsx:88` then matches the *first*
roll-taking event for that ensemble that day. A rehearsal + sectional on the same day means
afternoon marks get tagged to the morning `eventId`. Pass `{ ensembleId, eventId: event.id }`
and match on both. For joint rehearsals, land on the period picker instead of silently taking
`ensembleIds[0]`.

**D3 — fix the hint text** (`DirectorApp.tsx:109`): it describes cycling and a "Tardy" status;
the real UI is dedicated Absent/Late/Excused/Lesson buttons and "Late". Suggested copy:
*"Pick a rehearsal, then tap Absent, Late, or Excused — everyone else counts as present. Tap a
marked button again to clear it."*

**D4 — keep the roll screen lean.** `RollPeriod` mounts `useAllAttendance()` (the entire
attendance collection, unbounded — `useAttendance.ts:131-145`) just to draw 5 history dots. By
spring that is thousands of docs streaming under the director's thumb. Use a bounded query
(`where('ensembleId','==',…)` + recent-dates cutoff).

**D5 — never eat a correction silently.** `toggleAttendance` drops a second tap while the first
is settling (`useAttendance.ts:75-76`) — and the haptic fires only after the lock, so a dropped
tap gives zero feedback. Queue the latest intent per student (overwrite the optimistic value,
chain the write) or fire a distinct "rejected" buzz.

**D6 — two-line fix** in `writeStatus.ts:35`: allow up to ~3 concurrent undo entries instead of
replacing the only slot (`items = [...items, entry].slice(-3)`), so "delete event, then delete
override" doesn't silently discard the first restore.

### 1.2 Schedule management

**Verdict: excellent for one-off changes — swap/shift/cancel with auto-generated family-facing
banners, snapshots, and true revert is a standout. The gap is recurrence.**

| # | Finding | Severity | Effort |
|---|---------|----------|--------|
| D8 | **No recurring-event support; weekly rehearsals exist only via hardcoded 2026-27 seed code** | **High** | Medium |
| D9 | ICS import mangles UTC times (`Z` stripped, not converted) and ignores RRULE | Medium | Medium |
| D10 | Schedule list view renders every future event with per-card roster resolution | Medium | Low |

**D8 — next school year currently requires a code change and redeploy.**
`EventForm.tsx` has no repeat control; the weekly pattern lives in `seedCalendar.ts` as
hardcoded 2026-27 dates, rooms, and a `NO_SCHOOL` set (`seedCalendar.ts:17-49,190-191`),
surfaced as one-shot "Seed 2026-27" buttons. The data model (one doc per dated session) is
fine — add a lightweight "Repeats" section that expands client-side on save:

```tsx
// EventForm state
repeat?: { days: number[] /* 0-6 */; until: string /* YYYY-MM-DD */ };

// On save — reuse the seeder's proven 499-per-batch chunking:
for (let d = form.date; d <= repeat.until; d = addDays(d, 1)) {
  if (repeat.days.includes(dow(d)) && !noSchoolDates.has(d)) {
    batch.set(doc(db, 'events', `reh-${d}-${ensId}-${start}`), { ...eventData, date: d });
  }
}
```

Move the no-school list into a Firestore config doc a director can edit, and next August's
setup becomes data entry instead of a deploy.

**D9 — silent wrong times on import.** `IcsImport.tsx:52-64` slices `HHMM` from the raw string
and strips the `Z` without converting — Google Calendar's typical UTC export
(`DTSTART:20261015T230000Z` = 7 PM Miami) imports as 23:00. Convert via `new Date(iso)` before
extracting HH:MM, and show a preview warning for RRULE events ("recurring — only the first
date will import") or expand simple weekly rules.

### 1.3 Admin dashboard & navigation

**Verdict: already tight.** Today is the landing tab with one-tap Take Roll per rehearsal card,
quick actions, a follow-up queue, and a Cmd+K command palette with live "where is this student
right now" answers. Role handling is clean (owner-only Directors screen; purpose-built
single-screen shells for Teacher and Personnel Assistant).

The one structural improvement worth making (D11, medium impact / medium effort): **on phones,
promote the four daily-loop items (`NAV_TOP` — Today, Take Roll, Schedule, Who's Out) to a
fixed bottom tab bar** instead of living only inside the hamburger overlay
(`dirShell.css:94-96`, `DirectorApp.tsx:342-434`). The data structure is already shared with
the desktop rail; this turns "anywhere → Take Roll" from two taps into one and gives the roll
screen an always-visible escape hatch. Keep safe-area padding consistent with
`dir-roll-sticky-bottom`.

Also: the printed QR kit hardcodes `https://d5nf9kcskk-byte.github.io/nwsa-music-hub/`
(`QrKitView.tsx:12-14`) into physical posters and folder slips. Derive it from
`window.location.origin + import.meta.env.BASE_URL` (and consider a short custom domain — it
would also fix the unmemorable human-typeable URL under every printed code).

### 1.4 QR / barcode self-check-in — a product decision, not a gap

There is **no self-check-in flow** today: `src/director/qr/` is an outbound-link print kit and
`ensembles/js/qr.js` is just a QR generator. Recommendation: **don't build one.** Exception-only
roll already makes the all-present case one tap, and scanning 60 students through a phone
camera is slower and socially clumsier than tapping the 3–5 exceptions. If self-check-in is
ever wanted for very large ensembles, the coherent design is a per-rehearsal rotating code
whose scan writes a "present" ping — but note that requires an unauthenticated student write
path in `firestore.rules`, a security surface the current model deliberately avoids. The
attendance-integrity cost is real (see S4: spoofed planned absences — same class of problem).

## 3. Security & data protection

Every critical/high finding here was independently re-verified against the code
(verdicts noted). Ordered by real-world risk:

| # | Finding | Severity | Verified |
|---|---------|----------|----------|
| S1 | **Real 2025-26 roster (86 minors: names, grades, instruments) committed to the repo and shipped in the public director JS chunk; git history preserves it permanently** | **Critical** | CONFIRMED |
| S2 | **`students` + `seatingCharts` world-readable via unauthenticated Firestore REST; per-student ICS feeds published as static guessable files; no opt-out flag exists** | **High** | CONFIRMED |
| S3 | `rosterOverrides` world-readable → leaks private-lesson pull-outs + free-text reasons the `lessons` collection was explicitly locked down to protect | Medium | — |
| S4 | Unauthenticated `plannedAbsences` create → spoofed absence reports for any student ("tap Excused to accept" nudge), anonymous write spam, no App Check | Medium | — |
| S5 | `storage.rules` `isStaff()` forgets to exclude the `assistant` role (latent — Storage not yet enabled) | Medium | — |
| S6 | Rules allowlist never checks `email_verified` (or provider) — one console toggle away from allowlist takeover | Medium | — |
| S7 | Student PII persists in IndexedDB after sign-out (persistent cache never cleared; auth persistence is local-forever) | Medium | — |
| S8 | CSV exports don't neutralize spreadsheet formula injection (`=`, `+`, `-`, `@`) | Low | — |
| S9 | No CSP meta tag (GitHub Pages can't set headers, so a meta tag is the only option) | Low | — |
| S10 | Any teacher can read every teacher's lessons; audit-log `name`/`role`/`action` fields are spoofable by any allowlisted account | Low/Info | — |

### S1 — purge the committed roster (do this before anything else)

`src/director/baseline2526.ts` says it plainly: *"2025-26 baseline roster (from the director's
spreadsheet export)"* — 86 real students with full names and grades (lines 21–106). Older real
rosters also live in `scripts/migrate.js:42-235` and `src/director/seedData.ts`. This is not
just a repo problem: `RosterView.tsx:16-17` imports the reset path, so **the roster compiles
into the DirectorApp chunk served publicly from GitHub Pages**, and git history preserves it
even after the files are edited.

Remediation, in order:
1. Replace the data in all three files with clearly fictional records (the repo's own
   `docs/sample-roster.csv` shows the house style) — or better, load baselines from a
   runtime-uploaded file: `resetBaseline.ts:89` (`importBaselineContacts`) already proves that
   pattern works.
2. Purge history with `git filter-repo` (or BFG) and force-push — a plain revert leaves every
   name in history; if that's disruptive, migrate to a fresh repo.
3. Verify the deployed `DirectorApp-*.js` chunk no longer contains any student name.

### S2 — decide the public-roster question deliberately, with the school

The world-readable `students` collection (`firestore.rules:90`) and public per-student pages
are a *design choice* the rules header documents. But under FERPA, name + grade level +
activity participation are "directory information" — publishable **only** while honoring
parental opt-outs, and there is currently no opt-out field, so the app cannot honor one.
Minimum path:

- Add `excludeFromPublic?: boolean` to `Student`; filter it in public reads (either move reads
  behind a public-safe projection collection maintained by staff writes, or accept
  client-side filtering as the interim while the flag is new).
- Skip opted-out students in `scripts/generate-feeds.mjs` per-student ICS generation.
- Consider first name + last initial on all public surfaces.
- Get written sign-off from New World School of the Arts administration that the public
  roster + per-student schedule feeds match their directory-information policy.

### S4/S6 — rules hardening (copy-paste ready)

```js
// firestore.rules — signedIn(): require a verified email so enabling another
// auth provider in the console can never hand staff access to an unverified
// claimant of an allowlisted address. Mirror in storage.rules isStaff().
function signedIn() {
  return request.auth != null
    && request.auth.token.email_verified == true
    && exists(/databases/$(database)/documents/directors/$(request.auth.token.email));
}

// plannedAbsences — tie submissions to real students and bound every field:
allow create: if request.resource.data.keys().hasOnly(
      ['studentId','studentName','date','reason','submittedAt','status'])
  && request.resource.data.studentId is string
  && exists(/databases/$(database)/documents/students/$(request.resource.data.studentId))
  && request.resource.data.studentName is string
  && request.resource.data.studentName.size() <= 120
  && request.resource.data.date is string
  && request.resource.data.date.matches('\\d{4}-\\d{2}-\\d{2}')
  && request.resource.data.submittedAt is number
  && request.resource.data.reason is string
  && request.resource.data.reason.size() <= 300
  && request.resource.data.status == 'pending';
```

Plus: enable **Firebase App Check** (reCAPTCHA Enterprise) to throttle anonymous write volume,
and render pre-reported absences to staff as *claims* ("reported from an unverified device"),
since anyone who can read the public roster can currently file one for any student.

Fix S5 now while it's latent — one line in `storage.rules:33`:
`directorDoc().role != 'teacher' && directorDoc().role != 'assistant'` — so enabling Storage
later can't silently grant an attendance-only assistant write access to the public documents
repository.

### 4.1 Offline & PWA: one adoption closes most of it

The single highest-leverage change in this audit: **replace the 45-line hand-rolled `sw.js` +
`swCacheBust` plugin with `vite-plugin-pwa` (Workbox `generateSW`)**. It fixes A1 and A2
structurally — a precache manifest of *every* built asset including the lazy director chunk,
atomic cache versioning, correct navigation fallback that never caches a 404 as the shell —
and public/ images (logo, campus map) come along for free. Keep the existing update toast via
`registerType: 'prompt'`.

```ts
// vite.config.ts
import { VitePWA } from 'vite-plugin-pwa';
export default defineConfig({
  base: '/nwsa-music-hub/',
  plugins: [
    react(),
    VitePWA({
      registerType: 'prompt',
      workbox: {
        globPatterns: ['**/*.{js,css,html,svg,png,ico,json}'],
        navigateFallback: '/nwsa-music-hub/index.html',
        navigateFallbackDenylist: [/^\/nwsa-music-hub\/feeds\//],
      },
      manifest: false, // keep the existing public/manifest.json
    }),
  ],
});
```

If you keep the hand-rolled SW instead, the two mandatory patches are: a `res.ok` guard before
every `cache.put` (never cache 404.html as the shell), and precaching the built asset list at
install.

Then finish the offline story the attendance path already gets right:

- **A4:** for queued-safe mutations, stop awaiting server ack — generate the id client-side
  (`const ref = doc(collection(db,'students')); setDoc(ref, data)`), close the form
  immediately, and let `trackWrite` race a short timeout that resolves to a "queued (offline)"
  state. `StatusStrips` already promises *"changes sync when you reconnect"* — make the forms
  honor it.
- **A5:** grant provisional director access instantly from `getDocFromCache`, re-verifying in
  the background (or swap `getDoc` for `onSnapshot`, which delivers cache-first).
- **A8:** `persistentMultipleTabManager()` — one line.

  resolving rosters inside each card's render.

### 4.3 What NOT to modernize (explicit non-recommendations)

- **No state library (TanStack Query/Zustand/Redux) and no local-first sync layer.** The
  Firestore SDK already deduplicates identical listeners onto one wire subscription, the
  persistent cache serves re-mounts instantly from IndexedDB, and the per-hook `onSnapshot`
  pattern is idiomatic and debuggable for a solo maintainer. Migration would touch all 18
  hooks for zero user-visible gain.
- **No Tailwind/shadcn.** The ~40 bespoke CSS files form a coherent, hand-rolled design system
  with better a11y engineering than most component libraries deliver out of the box; migration
  is weeks of churn for zero user value.
- **No SSR/Next.** Static GH Pages + Firestore listeners is the right shape here.
- **IndexedDB/PWA ambitions are already satisfied** by `persistentLocalCache` + the SW fix
  above — don't add another offline layer.

The stack (React 19, Vite 8, react-router 8, TS 6, ESLint 10) is current. Remaining
maintainer-protection budget goes to: `strictNullChecks` as one dedicated pass (A3), `npm ci`
+ a PR workflow running `lint && tsc -b`, and **vitest on the pure modules only** —
`rosterResolver`, `lessonConflicts`, `scoreOrder`, announcement visibility, `quickAdd` date
parsing, and an ICS round-trip fixture with a newline/comma/semicolon note (catches A10
forever). No component/DOM testing needed; roughly an afternoon.

### 4.4 Repo hygiene

The legacy `ensembles/` vanilla-JS app (a parked parallel reimplementation, per its own
`RECOVERED-FROM-LONGITUDE.md`) is confirmed **not built, not deployed, not linked** — but it
duplicates the whole product, shadows the live `/ensembles` route name, and is exactly where a

"Northwestern"-era strings. Preserve it on a tag (`git tag archive/ensembles-hub-vanilla`) and
delete it from `main`. `docs/` is real documentation, not build output — no action needed.
