# Third parties the Hub sends data to

Every outside service the NWSA Music Hub's code sends data to, what it gets, and where that vendor's privacy or data-processing terms live. Built from the code as of November 2026: the CSP in `vite.config.ts`, `firebase.json`, `extensions/`, `functions/src/`, `scripts/` and `.github/workflows/`. Links checked 2026-11-03. Parent-facing summary: [privacy-notice.md](privacy-notice.md).

If you add a service, add a row here in the same change.

| Vendor / service | What it does for the Hub | What data it receives | Terms |
|---|---|---|---|
| **Google Firebase / Google Cloud: Cloud Firestore** | The database | Everything the Hub stores: rosters, schedules, contacts, attendance, grades, notes, form answers, check-in records, sent-mail copies, staff accounts and sign-in logs | [Firebase Data Processing and Security Terms](https://firebase.google.com/terms/data-processing-terms); [Firebase privacy and security](https://firebase.google.com/support/privacy); [Google Cloud Data Processing Addendum](https://cloud.google.com/terms/data-processing-addendum) |
| **Google Firebase: Cloud Storage** | File storage | Staff-uploaded documents and handouts; student playing-exam videos; concert check-in photos; office excuse-note photos; signed permission PDFs (emergency contacts, medical notes) | Same as above |
| **Google Firebase: Authentication** | Staff sign-in | Staff Google account email, name and sign-in tokens. Students do not sign in | Same as above |
| **Google Cloud Functions** (Firebase) | Server code: concert door check-in, private calendar feeds, turning requests into emails, video upload assembly | Whatever each function handles: check-in email and photo, lesson and booking details for a staff member's own calendar, the content of each outgoing email | Same as above |
| **Google reCAPTCHA Enterprise / Fraud Defense** (via Firebase App Check) | Tells real browsers from automated traffic, when turned on | Browser and device signals from the visitor's browser, scored by Google. No Hub records | [Google Cloud Data Processing Addendum](https://cloud.google.com/terms/data-processing-addendum); [Google Privacy Policy](https://policies.google.com/privacy) |
| **Firebase Cloud Messaging** (staff trial on; families built and switched off, #push) | Phone alerts when something happening today is changed or cancelled | The device's push token and the alert text (the event's title or ensemble names and the director's change note, all already public). Never a student name. Subscriptions store the token, the ensembles followed, the language, and on a family device the saved students' ids; nobody can read them through the app | [Firebase Data Processing and Security Terms](https://firebase.google.com/terms/data-processing-terms) |
| **Trigger Email extension** (`firebase/firestore-send-email`) | Sends the emails queued in the `mail` collection | Recipient addresses, subject and body: form confirmations, answers to absence and copy requests, lesson logs and grade reports to families. Sent-mail copies are kept (`TTL_EXPIRE_TYPE=never` in `extensions/firestore-send-email.env`) | Runs inside the Firebase project; same Firebase terms |
| **Gmail** (Google), the extension's mail transport | SMTP delivery from the music division's Gmail account | The same emails as above, sent from and stored in that account's Sent mail | [Google Privacy Policy](https://policies.google.com/privacy); [Google Terms of Service](https://policies.google.com/terms) |
| **Google Drive** (directors' Drive) | Archive copies a director can browse outside the Hub | Concert check-in photos and the attendance CSV (name, grade, instrument, school email, times), filed by `scripts/sync-drive-photos.mjs`; playing-exam videos copied into a director's assignment folder by `scripts/sync-drive-videos.mjs`. A director connects the folder with a Google popup (`drive.file` scope) | [Google Privacy Policy](https://policies.google.com/privacy); for a school Workspace account, [Cloud Data Processing Addendum](https://workspace.google.com/terms/dpa_terms.html) |
| **GitHub Pages** | Hosts the public site | The built site, plus calendar files generated from the public projections only (per-student calendars carry names and lesson times). Visitors' requests go to GitHub's servers | [GitHub General Privacy Statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement); [GitHub customer terms and DPA](https://github.com/customer-terms) |
| **GitHub Actions** | Runs builds, feed refresh, scheduled syncs and admin scripts | Runners read Firestore with a service account. Feed builds read public projections only; the Drive syncs pass check-in photos and videos through the runner; admin scripts read what they are written to touch. Logs are public, so scripts print no student data | Same as GitHub Pages |
| **Microsoft 365** (the school district's tenant) | Source of the office attendance bulletin; destination of the urgent-announcement relay | The Hub READS the attendance bulletin from the school's Microsoft mailbox or OneDrive through Microsoft Graph (`scripts/fetch-attendance-bulletin.mjs`). Urgent announcements are queued in `notifyQueue` for a Power Automate flow, outside this repo, to post to Teams or email; announcement text is already public | [Microsoft Products and Services Data Protection Addendum](https://www.microsoft.com/licensing/docs/view/Microsoft-Products-and-Services-Data-Protection-Addendum-DPA) |
| **corsproxy.io** | Lets a director import an outside calendar (`.ics`) by URL | The calendar URL the director pastes, and that calendar's contents passing through. No Hub records | No privacy policy found as of 2026-11-03: [corsproxy.io](https://corsproxy.io) |
| **Anthropic** (Claude), weekly code review | Reviews the week's code changes | The repository's source code and probes of the PUBLIC site. Runs from a separate private repo; no Firestore records | [Commercial Terms](https://www.anthropic.com/legal/commercial-terms); [Data Processing Addendum](https://www.anthropic.com/legal/data-processing-addendum) |
| **Anthropic** (Claude API), Spanish banner drafter (built, OFF) | Drafts a Spanish version of a schedule change note the director just wrote, for the director to edit before saving (`draftChangeNoteEs` Cloud Function) | Only the English change note text, from a signed-in staff member. No event, roster, student or staff data. The function is not deployed and `features.bannerDrafter` is false, so nothing is sent today. How to turn it on: [banner-drafter.md](banner-drafter.md) | [Commercial Terms](https://www.anthropic.com/legal/commercial-terms); [Data Processing Addendum](https://www.anthropic.com/legal/data-processing-addendum) |

## Links, not data transfers

Pages also link out to IMSLP, YouTube, Google Maps, MapsIndoors, Google Calendar and Microsoft Forms. The Hub sends those sites nothing; a visitor who taps a link goes there directly.
